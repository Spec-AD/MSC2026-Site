### ❌ 致命 Bug：40 个路由使用 app. 而非 router.

**症状：** 5 个路由文件声明了 `router = express.Router()` 并导出 `module.exports = router`，但所有路由注册用的却是 `app.get()/app.post()` 而非 `router.get()/router.post()`。

**后果：** `app.js` 通过 `app.use(require('./routes/xxx'))` 加载这些模块时，由于路由注册到了全局 `app` 对象而非 `router`，**这些 API 端点完全不会被注册**，是死代码。

**受影响文件：**

| 文件 | 影响路由数 | 丧失的功能 |
|------|-----------|-----------|
| `social.js` | 17 | 好友系统（申请/接受/拒绝）、消息系统（CRUD/文件夹/星标）、管理员广播、预选赛成绩管理、**曲库列表 API** |
| `feedback.js` | 10 | 反馈提交/修改/删除/管理员标记、预选赛排行榜 |
| `admin.js` | 6 | 投诉系统（提交/列表/处理）、ADM 角色管理、员工列表 |
| `chunithm.js` | 6 | Chunithm 成绩同步导入（Diving-Fish）、曲库同步、用户设置 |
| `scoreLeaderboard.js` | 1 | 单曲排行榜（含好友范围） |

**总计：40 个 API 端点失效。**

### ⚠️ 次要问题

1. **`admin.js` 末尾残留 `app.listen(...)`** — 如果将来修复了 `app.` bug 后，这行会尝试启动第二个 HTTP 服务器
2. **`server.js` 旧文件仍保留** — 含 105 条旧路由定义，可作为备份参考，但长此以往建议删除或归档
3. **`social.js` 中混入了曲库 API** (`/api/songs`) — 本应属于 `songs.js` 路由模块，功能边界不清晰

### 🔧 修复方案

每个问题文件只需做两件事（以 `social.js` 为例）：

```javascript
// 旧代码（路由不生效）：
app.get('/api/messages', authMiddleware, async (req, res) => { ... });

// 新代码（替换 app → router）：
router.get('/api/messages', authMiddleware, async (req, res) => { ... });
```

另外删除 `admin.js` 底部的 `app.listen(...)` 行。

### 💡 建议

- 修复前跑一遍现有功能测试，确认当前线上哪些功能是老的 `server.js` 提供的，解耦后是否实际被降级
- 考虑添加一个 `routes/index.js` 统一管理路由注册，而不是在 `app.js` 中一行行 `require`
- 可引入 ESLint 规则禁止在路由文件中使用 `app.` 前缀
