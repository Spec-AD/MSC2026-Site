## 1. 背景与目标

### 问题现状

经过 b1.7 前两轮优化，osu! 功能模块已具备比较完善的能力（排行榜、BP 排行、玩家查询、谱面查询、多模式同步等），但存在严重的**用户路径缺失**和**体验不统一**问题：

1. **入口唯一性**：用户只能通过 `/profile/用户名/osu`（osu! 卡片入口）访问 osu 功能，但该页面不显示顶部导航 Tab；而 `/osu` 页面虽有所有 Tab，却没有公开入口路径
2. **档案信息贫瘠**：当前档案页面仅显示几项基本统计和 BP 列表，远达不到 osu! 官方资讯的丰富度
3. **排行榜体验粗糙**：头卡信息不全、颜色区分缺失、MOD 占位不足、Banner 和国旗等标识欠缺
4. **模式切换不直观**：S|T|C|M 单字母缩写缺乏可读性
5. **同步仍然异常**：老用户重新绑定时报错，客户端凭据需确认
6. **数据 Bug**：mania 模式 PERFECT=GREAT 相同值、lazer 客户端分数为 0
7. **无缓存**：页面切换后搜索状态、排行榜数据全部丢失
8. **字体缺失**：osu! 模块未使用 osu! 官方字体 Torus

### 目标

本次重构将 osu! 模块体验对齐 osu! 官方设计语言，补齐用户路径、统一 UI 规范、修复数据 Bug，为 PureBeat 的 osu! 社区功能奠定坚实基础。

## 2. [P0] 导航入口与 URL 归一

### 2.1 问题

当前存在两个独立路由路径：

| 路径 | 功能 | 问题 |
|:-----|:-----|:-----|
| `/profile/:username/osu` | 用户 osu! 档案 | 无顶部 Tab 导航栏，功能单一 |
| `/osu` | osu! 功能总入口 | 有完整 Tab 导航，但无公开入口路径 |

用户根本无法发现 `/osu` 页面存在。这不是可以靠"让用户自己打 URL"解决的问题。

### 2.2 方案：页面合并归一

两个页面合并为一个统一入口：**`/osu`**

#### 具体改动

**后端**（琉璃）：
- `GET /api/osu/profile/:username` — 当前 `getUserProfile` 端点保留并增强，确保 `/osu` 页面能加载任意用户（不仅是当前登录用户）的档案
- 用户未登录时查看 `/osu` → 显示当前用户的 osu! 档案（如果有绑定）
- 有 `?user=xxx` 参数时 → 加载指定用户的 osu! 档案

**前端**（凛月）：
- `/profile/:username/osu` 路由 → 重定向到 `/osu?user=:username`（或直接指向同一个组件）
- `/osu` 页面始终包含完整顶部 Tab 导航（我的档案 / BP 排行 / 最近通过 / 最近游玩 / 今日最佳 / 玩家查询 / 谱面查询 / 排行榜）
- **默认页（`/osu` index）**：显示当前用户的 osu! 档案（如果绑定）或提示绑定
- **`?user=xxx`**：加载指定用户的档案

#### 用户路径示意图

```
个人资料 → osu! 卡片 → /osu?user=xxx （有完整导航）
顶部导航 → osu! 入口 → /osu （有完整导航）
```

不论从哪个入口进入，用户都看到同一套完整的 Tab 导航。

### 2.3 前端改动清单

| 文件 | 改动 |
|:-----|:------|
| `App.jsx`（路由） | `/profile/:username/osu` → 重定向到 `/osu?user=:username` |
| `OsuProfile.jsx` | 支持 `?user=` 参数加载他人档案；合并到 OsuHome 的 Outlet |
| `OsuHome.jsx` | 保持现有导航结构不变 |
| `Profile.jsx`（osu! 卡片） | 卡片链接指向 `/osu?user=username` 而非 `/profile/username/osu` |

## 3. [P0] OAuth 同步修复

### 3.1 问题

老用户点击同步后提示需要重新绑定，但重新绑定跳转到 osu! 官网时提示：
> 请求参数无效，客户端未授权

### 3.2 原因

客户端凭据配置有误，或环境变量未生效。

### 3.3 修复方案

**琉璃排查并确认以下内容：**

1. **环境变量检查**：
   ```
   OSU_CLIENT_ID=49210
   OSU_CLIENT_SECRET=RFmKYn4BjpmtYogb4WjmhNKfQIemaJLw6VodBJiO
   ```
   - 确认 `.env`（server）中 `OSU_CLIENT_ID` / `OSU_CLIENT_SECRET` 已正确设置
   - 确认前端 `VITE_OSU_CLIENT_ID` 是否正确暴露
   - 确认生产环境（Zeabur）的环境变量已同步更新

2. **OAuth 授权 URL 确认**：
   - 跳转 URL 格式：`https://osu.ppy.sh/oauth/authorize?client_id=${clientId}&redirect_uri=${redirectUri}&response_type=code&scope=identify+public&state=${state}`
   - `redirect_uri` 是否与 osu! 官方开发者后台注册的一致？
   - scope 是否为 `identify+public`（空格编码后为 `identify+public`）

3. **Token refresh 流程检查**：
   - `services/osu/api.js` 中 refresh token 逻辑是否正确
   - refresh token 过期时是否优雅降级为要求重新绑定

### 3.4 验证标准

- 使用真实绑定账号测试全流程：绑定 → 同步 → 查看数据
- 使用已过期的 old token 测试重新绑定流程

## 4. [P0] Bug 修复：mania PERFECT=GREAT / Lazer 分数为 0

### 4.1 PERFECT 与 GREAT 数值相同（mania 模式）

**现象**：mania 模式下，排行榜条目的 PERFECT 计数与 GREAT 计数始终相同。

**根因猜测**：后端 OsuScore 模型中 `countPerf` 字段未正确映射。mania 模式下 osu! API 返回的 `statistics.count_perfect` 可能被映射到了 `count300`（countGreat）而非 `countPerf`。

**修复要求**：
- 琉璃检查 `models/OsuScore.js` 中 mania 成绩的字段映射逻辑
- 确认 `statistics.count_perfect` 是否被正确解析为独立的 `countPerf` 字段
- 如果 `count300` 在 mania 中包含了 PERFECT 的计数，需要做拆分或增加字段

### 4.2 Lazer 客户端分数为 0

**现象**：
- stable 端上传的成绩：分数正常 ✅
- lazer 端上传的成绩：分数始终为 0 ❌

**根因猜测**：lazer 使用 `total_score`（标化计分制）而非 `legacy_total_score`。当前排行榜 API 固定传 `legacy=1` 可能只取了 `legacy_total_score`，但 lazer 端没有 legacy 分数，导致为 0。

**修复要求**：
- 琉璃检查 `services/osu/leaderboard.js`、`services/osu/sync.js` 中的分数读取逻辑
- 对于 `legacy_total_score` 为 null/0 的条目，fallback 到 `total_score`
- 确保 OsuScore 模型中同时保存 `score`（主分数字段）和 `legacy_score`（备用字段）

## 10. [P2] 搜索栏全宽 + 搜索状态缓存

### 10.1 搜索栏全宽

当前 `OsuLeaderboard.jsx` 中的搜索栏横向宽度太窄，需要改为全宽。

```
┌──────────────────────────────────────────────────────────────┐
```

### 10.2 搜索状态缓存

**问题**：用户从 排行榜 → BP 排行 → 排行榜，回来后搜索状态丢失，需要重新填写。

**方案**：
- 使用 React Context 或 Zustand store 缓存 osu! 页面的搜索状态
- 缓存内容：
  - 排行榜：搜索的 BID + 返回数据
  - 玩家查询：搜索关键字 + 返回数据  
  - 谱面查询：搜索关键字 + 返回数据
- 缓存仅在当前 session 内有效（页面刷新后清除）

### 10.3 前端改动

## 11. [P2] 排行榜缓存

### 11.1 问题

每次切换页面后重新进入排行榜都需要重新请求 API，且 osu! API 有速率限制。

### 11.2 方案

**前端内存缓存**（短期，与 §10 同 context）：
- 缓存排行榜数据（key=`leaderboard:{bid}`, TTL=5min）
- 缓存谱面信息（key=`beatmap:{bid}`, TTL=10min）
- 缓存玩家查询结果（key=`info:{query}`, TTL=5min）

**后端 Redis/内存缓存**（琉璃评估可行性）：
- 热门谱面排行榜缓存（TTL=1-2min）
- 减少对 osu! API 的重复请求

## 13. [P2] BP 背景曲绘渐变渲染

### 13.1 要求

BP 排行的每一个「框」的背景，应当是该歌曲**曲绘的渐变渲染**。

### 13.2 实现方案

1. 获取 `score.coverUrl`（曲绘 URL）
2. 使用 CSS `background-image` 渐变覆盖：

   ```css
     to right,
     rgba(0,0,0,0.8) 0%,
     rgba(0,0,0,0.4) 50%,
     rgba(0,0,0,0.8) 100%
   ), url(${coverUrl});
   background-size: cover;
   background-position: center;
   ```

### 13.3 替代方案

## 15. 字体规范

### 15.1 字体文件

```
client/public/fonts/
├── Torus-Alternate-Bold.fnt      ← osu! 模块标题/粗体
├── Torus-Alternate-Regular.fnt   ← osu! 模块正文
```

### 15.2 应用范围

**仅 osu! 模块**（`/osu` 路径下所有页面）使用 Torus 字体，其他页面保持现有字体。

### 15.3 实现方式

```css
/* 在 osu! 模块的根级 container 上应用 */
.osu-font {
  font-family: 'Torus Alternate', 'Torus', system-ui, sans-serif;
}
```

如 `.fnt` 是位图字体格式，可能需要转换为 Web 可用格式（woff/woff2），或使用 CSS `@font-face` 直接加载 bitmap font。

**凛月确定最佳加载方式**：

- 如果 `.fnt` 带 `.png` 贴图 → 需要 web-font 转换工具
- 也可以暂时用 `@font-face` 指定常规字体文件路径
- 确认文件夹中是否有对应的 `.ttf` 或 `.woff` 文件
- 目前 `fonts/` 下只有 `.fnt` 文件，可能需要找对应的 `.ttf` 源文件或使用转换工具
