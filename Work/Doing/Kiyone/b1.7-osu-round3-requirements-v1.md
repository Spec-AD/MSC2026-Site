### 2.1 点击用户名 → `/osu/info?q=xxx` 未触发搜索

**说明**：点击用户名跳到 `/osu/info?q=username` 这个目标方向是**对的** ✅（Magix 确认），但当前 `/osu/info?q=xxx` 不会在页面加载时自动触发搜索，导致用户看到的是空结果。

**修复**：`OsuInfo.jsx` 在 mount 时读取 `?q=` 参数，若有值则自动触发搜索执行。

**涉及文件**：
| 文件 | 改动 |
|:-----|:------|
| `pages/OsuInfo.jsx` | `useEffect` 读取 `q` search param，自动调搜索 |

## 3. 新增功能：搜索历史

### 3.1 需求概述

在 `osuCache`（Zustand store）中新增搜索历史功能，分别记录 BID 搜索和玩家名搜索的历史记录，各最多保留 10 条。

搜索历史在切换 Tab 或离开页面后仍保留（session 内有效，刷新页面后清除）。

### 3.2 BID 搜索历史

**触发时机**：用户点击排行榜搜索按钮时自动记录

**单条内容**：
```
┌──────────────────────────────────────────────┐
│ [封面] bid_123456  曲名              [模式PNG]│
│        难度名                                 │
└──────────────────────────────────────────────┘
```

| 字段 | 来源 | 说明 |
|:-----|:------|:------|
| bid | `beatmap.beatmapId` | 搜索的谱面 ID |
| 封面 | `beatmap.coverUrl` | 曲绘封面，小尺寸 |
| 曲名 | `beatmap.title` 或 `titleUnicode` | 谱面名称 |
| 难度名 | `beatmap.version` | 难度名称 |
| 模式 | `beatmap.mode` | 用 Ruleset PNG 图标表示 |

**去重逻辑**：同 BID 重复搜索时，将该条目移到历史顶部，不重复添加。

**交互**：
- 点击历史条目 → 直接跳转到该 BID 的排行榜（`/osu/leaderboard/{bid}`）
- 历史区域显示在搜索栏下方

### 3.3 玩家搜索历史

**触发时机**：用户在 OsuInfo 点击搜索时自动记录

**单条内容**：
```
┌──────────────────────────────────────────────┐
│ [头像]  用户名          [国旗]              │
│         玩家 ID                              │
└──────────────────────────────────────────────┘
```

| 字段 | 来源 | 说明 |
|:-----|:------|:------|
| 头像 | `result.avatarUrl` | 搜索结果中解析 |
| 用户名 | `result.username` | 玩家名 |
| 国家 | `result.countryCode` | 使用 CountryFlag 组件 |
| 玩家 ID | `result.osuId` | osu! 玩家 ID 或本地用户 ID |

**去重逻辑**：同用户名重复搜索时，将该条目移到历史顶部。

**交互**：
- 点击历史条目 → 直接触发对该用户名的查询
- 历史区域显示在 OsuInfo 搜索栏下方

### 3.4 前端改动清单

| 文件 | 改动 |
|:-----|:------|
| `store/osuCache.js` | 新增 `leaderboardHistory[]`（BID）、`playerHistory[]`（玩家），各 max 10 条；去重逻辑；`addLeaderboardHistory` / `addPlayerHistory` actions |
| `pages/OsuLeaderboard.jsx` | 搜索成功后记录 BID 历史；新增搜索历史 UI（搜索栏下方） |
| `pages/OsuInfo.jsx` | 搜索成功后记录玩家历史；新增搜索历史 UI（搜索栏下方）；读取 `?q=` 参数自动搜索 |
| (新建) `components/OsuSearchHistory.jsx` | 通用搜索历史组件（可复用），接收条目列表+点击回调 |

### 3.5 后端改动

无。搜索历史纯前端实现，数据存在 Zustand store 中（session 级）。
